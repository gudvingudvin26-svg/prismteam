# Руководство для участников проекта

## Git Flow

- Основные ветки:
  - `main` – стабильная версия, всегда готова к релизу.
  - `develop` – основная ветка разработки, содержит последние изменения.
- Вспомогательные ветки:
  - `feature/*` – для новых функций. Создаётся от `develop`, вливается обратно через PR.
  - `bugfix/*` – для исправления ошибок в разработке.
  - `release/*` – для подготовки релиза (от `develop`, вливается в `main` и `develop`).
  - `hotfix/*` – для срочных правок в продакшене (от `main`, вливается в `main` и `develop`).

## Именование веток

- `feature/краткое-описание` (например, `feature/add-quiz-creator`)
- `bugfix/описание-бага`
- `release/v1.2.3`
- `hotfix/критическая-проблема`

## Соглашения по коммитам

Используйте [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` – новая функциональность
- `fix:` – исправление ошибки
- `docs:` – изменения документации
- `style:` – форматирование, опечатки и т.д.
- `refactor:` – рефакторинг кода
- `test:` – добавление или изменение тестов
- `chore:` – обновление зависимостей, настройки CI

Пример: `feat: add user authentication`

## Процесс работы

1. Создать задачу (issue) в репозитории.
2. Создать ветку от `develop` согласно соглашению.
3. Выполнить изменения, закоммитить с понятным сообщением.
4. Открыть Merge Request (Pull Request) в `develop`.
5. Убедиться, что все проверки CI (линтеры, тесты) проходят успешно.
6. Получить одобрение хотя бы одного другого разработчика.
7. Выполнить слияние (с сохранением истории, используя "merge commit").

## Требования к коду

- Все изменения должны сопровождаться соответствующими тестами.
- Код должен проходить линтеры (для Python – flake8, black; для JavaScript – ESLint).
- Документация API (если изменяется) должна быть обновлена.
